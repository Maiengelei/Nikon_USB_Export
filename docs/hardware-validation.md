# Z8 双卡验收

## macOS 1.0（构建 6）成品验收 · 2026-11-17

在 Apple 芯片 Mac、macOS 27.2.1 和 Xcode 27.2 上，从 Release 归档制作 ZIP，解压至新目录后启动其中的应用。在应用窗口选择临时导出目录，从两张卡各预览并导出一张 NEF。导出文件与前一轮独立读取的 SHA-256 均相符。

| 导出路径 | 字节数 | SHA-256 |
| --- | ---: | --- |
| `卡1/DCIM/100GENOL/GEN_0432.NEF` | 49,515,569 | `a0395707d1ced665ff3d1233a5f957be993402254f0d9be17ac5aece1fb86831` |
| `卡2/DCIM/100GENOL/GEN_0486.NEF` | 50,821,665 | `46ab5957ed38bd8aabd858c732d6dbfb8a07be153f593c80421ae59ce1305285` |

- 两个卡槽可分别浏览，选择目标后双卡导出按钮可用。再次导出卡 2 的样本，应用报告写入 0 张、同名同长度跳过 1 张。
- Mac 测试共 31 项，全部通过。主应用、XPC 服务及三个 Nikon 运行库都包含 arm64、x86_64。Intel 架构仅验证了构建和签名。
- 主应用和 XPC 服务均为 1.0（6），最低 macOS 14。主应用含现代图标资源和兼容图标 `AppIcon.icns`，已查看 macOS 27 的 256 和 32 像素渲染。
- 归档与解压副本均通过 `codesign --verify --deep --strict --all-architectures`。当前验收包使用 ad-hoc 签名，本机有效代码签名身份数为 0，`spctl --assess --type execute` 返回 `rejected`。公开分发还需 Developer ID 签名与 Apple 公证。

## 2026-11-16 实测

在 Apple 芯片 Mac 上使用 macOS 27.2.1、Xcode 27.2 和 Nikon Remote SDK 2.1.0。测试经应用的相机发现、SDK 服务和 ImageCaptureCore 传输入口运行，样本写入应用的本机临时目录。

| 检查项 | 观测结果 |
| --- | --- |
| 双卡识别 | 卡 1 为 `0x00010001`，276 张照片。卡 2 为 `0x00020001`，55 张照片。两卡的 Z8 卷标与存储 ID 一致。 |
| 构建与回归 | Release 生成 arm64、x86_64 双架构应用，嵌套签名通过严格校验。arm64 测试运行 31 项，全部通过。 |
| 目录一致性 | 两卡共有 335 个对象。批量和逐对象读取三轮交错对照，各对象的标识、存储、父目录、格式、文件名、字节数和完整相对路径一致。 |
| 目录耗时 | 同一已打开的 USB 会话内，三轮完整双卡目录扫描的中位数为批量 0.136 秒、逐对象 0.940 秒。批量方式两卡各用 5 次属性请求。此计时不含 SDK 发现和打开会话。 |
| 预览与导出 | 两卡各读取一张 NEF 的缩略图并导出原片。文件为 49,515,569 和 50,821,665 字节，分别与再次从相机独立读取的原片逐字节相同。 |
| 同名处理 | 在相同目标重试，两张样本分别计为同名同长度跳过。另在临时目录预置同名的 1 字节文件，两次均报告长度冲突。 |
| 拍摄事件 | 操作机身快门后收到 `0x4002`。旧目录和卡槽关联立即清空，刷新后卡 1 有 279 张、卡 2 有 55 张。 |
| 卡 1 单卡 | 重新接好 USB 后，应用只列出卡 1（`0x00010001`），共 279 张照片，双卡导出停用。 |
| 装回卡 2 | 关机时应用清空旧卡槽关联。装回 SD 卡并开机后，同一应用进程自动重连，约 6.1 秒后重新列出卡 1 的 279 张和卡 2 的 55 张照片，双卡导出恢复可用。计时从重新发现 USB 机身开始。 |

## 复验步骤

1. 用机身回放确认两卡各有可辨认的测试照片。通过 USB 连接后，核对卷标、存储 ID、卡槽和照片数。在工具栏复制读取记录，保存本次扫描方式与耗时。
2. 在每张卡各选一张照片，打开缩略图并导出到空文件夹。确认原片位于对应的 `卡1`、`卡2` 路径。换一个空文件夹再导出一次，用 `cmp` 核对两次导出的同一原片。
3. 重复导出至第一个目标，应计为同名同长度跳过。在另一个测试目标按相同路径预置一个不同长度的文件，重新导出应保留该文件，并在冲突清单显示路径和两侧字节数。
4. 保持目录打开，在机身拍摄。确认旧卡槽和导出按钮及时失效；刷新后能看到新照片。
5. 等存储卡指示灯熄灭，关机取出卡 2 再开机。确认只出现卡 1，双卡导出停用。再次关机装回卡 2 并开机后，确认两张卡重新识别。
6. 按 README 中的 `xcodebuild ... test` 命令运行回归测试。可重复注入的场景包括 USB 超时后的界面失效、批量属性缺失时回退、原片短读，以及在写盘期间出现同名目标。
